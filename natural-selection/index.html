下面用的是一个真实存在、能在游戏里跑起来的难度：Hazard 9 · 物竞天择。它用到的 CD2 能力比较全面——动态取值、变量池、波次生成、敌人描述符、底层属性都用上了。

为什么拿它当样本：这个难度是本站作者自己做的，并且已经在游戏里实测跑过。拿自己的东西拆解有两个好处：一是讲解不会猜错——每一处为什么这么写，都是设计时就定下来的，不用靠猜别人的意图；二是每一段都能跑——你照着抄不会碰上「看着是对的、进游戏却不生效或者直接报错」这类问题。

这里写的不是「这个难度多好玩」，而是「它想实现某个效果时，具体是怎么拼出来的」。每一步都给出对应的真实代码，你可以照着改。源文件：Hazard 9 · 物竞天择 · v0.18.13（JSON，210 KB）

怎么读这页：这页按由浅入深排，建议从头顺着看——①~④ 各只用到一个到几个原语，学会了再看 ⑤⑥ 这两套系统。第一遍只看每个功能的流程条、「它做了什么」和精简骨架；「实现拆解」是你动手写类似功能时的对照参考，可以整节跳过。

阅读前需要知道的事

  1. 六个功能按「由浅入深」排列，不是按在难度里的重要性排的。 顺序是 ① 硝石经济 → ② 勘探者无人机 → ③ 锁血 → ④ 阶段评级与三种啤酒 → ⑤ 生态重置 → ⑥ 物竞天择（难度见上面的功能索引表）。前四个是单个原语的用法，后两个是把很多原语拼成一套系统。
  2. ② 和 ③ 共用同一个开关（Vars.医疗无人机）：② 用它开回血与减伤，③ 用它锁血。不是两个无人机，是一个变量的两组下游——这本身就是一个要学的点（见 ③ 的第 4 步）。

功能 ① · 硝石经济改造

断源→记账→加倍率→计数→结算→播报

它做了什么

地图本来会长硝石，作者把产出关掉，改成自己记一本账：每击杀一种「固定单位」就往账上记点数，而点数还乘着一个会自己往上涨的倍率——杀得越密，硝石攒得越快。账上每满 60 点就送一次免费补给，最多 6 次，每叫一次补给再扣掉一次。「免费」不是打折，是把补给要花的硝石直接乘 0。

读取固定单位击杀事件 / 地图时间 / 补给调用次数 / 存入资源
判断硝石存量每跨过 60 的整数倍 → 免费补给次数 +1
输出Resupply.Cost
指向变量 → 还有免费次数时整个成本为 0

实现拆解

① 关掉地图硝石，把补给成本换成变量引用

这一步在算什么：先把两个入口铺好：地图硝石产出关掉，补给成本改成读变量。

① · 详解：公式与推演

NitraMultiplier: 0 只解决了「没有硝石」，没解决「硝石从哪来」，所以必须另建账本。补给这一侧的关键在于 Resupply 里只有一个 Cost 字段，而且它的值不是数字，是 {"Var":"补给硝石量"}。把成本换成变量引用之后，任何读取补给成本的地方都自动跟着变量走，不必在 Resupply 里写条件分支——一处改、处处生效。

Delta 把「累计击杀数」换成「这一帧新增的击杀数」，于是每次击杀只入库一次点数。这就是事件累加器的标准写法，后面所有「击杀计数」都在复用它。五个来源各自用 Multiply(点数, Delta(EnemiesKilled)) 加权后 Add 到一起，外层 Accumulate 配 Initial:0、Min:0，账本不允许出现负数。

④ 免费补给次数：Sequence 既是计数器也是上限

这一步在算什么：每满 60 点换一次免费补给，最多 6 次；每叫一次补给扣掉一次。

分支条件
A开局 15–18 秒窗口（TriggerOnce 包住，只给一次）
BSecondaryFinished
次要任务完成
C每存入 120 单位金或压缩金（Floor(Divide(…, 120))）
D生态重置激活
E玩家阶段表现锁定 == 6（每个阶段周期只放行一次）
F每满 60 硝石：TriggerOnChange(RiseOnly, Floor(硝石存量 / 60))
G推车任务开局 12 秒
④ · 详解：公式与推演

Sequence 定义状态集合，Next 加分、Previous 减分、Repeat:false 封顶；变量自己不记录「为什么加减」，两个方向都由外部事件驱动。Next 一共 A–G 七个加分口，硝石只是其中一条：

F 分支用的是 Floor 上升沿，不是取模加去重标记：存量 0→59 时 Floor 恒为 0 不触发，跨过 60 的那一瞬间变成 1 触发一次，120 时变成 2 再触发一次。一个 Floor 就替代了「余数判断 + 去重锁存」。

Previous 里的 TriggerDelay N:0.5 是必须的：Resupply.Cost 在调用补给那一刻被读取，如果先扣次数，最后一次免费补给会被算成收费。延迟 0.5 秒再扣，读成本时次数还没掉。

⑤ 补给硝石量：免费是乘 0，不是减免

这一步在算什么：「免费」的实现是把成本乘 0，而不是去改成本数字。

⑤ · 详解：公式与推演

补给硝石量 等于基础量乘以 IfFloat(免费补给次数 > 0, Then:0, Else:1)。它不是「免费时降价」，而是把成本整体乘 0。基础量本身按任务类型走：Default:60，推车任务再按 ByEscortPhase 分档 60 / 50 / 40 / 35 / 30 / 30。用乘 0 掩码而不是在 Resupply 里写分支，好处是补给成本始终只有一个变量引用，任何读它的地方都自动生效。

⑤ Else 必须显式写 1，颜色只是 Materials

这一步在算什么：条件乘子必须写 Else，漏了整条链归零；颜色只是外观，逻辑只认 ED id。

② LockFloat 当采样保持器

这一步在算什么：LockFloat 的两种接法，以及它为什么能当「采样保持器」。

② · 详解：公式与推演

LockFloat 以顶层原语出现在全文 15 个变量里，只有两种接法。接 Lock（布尔门控采样，只在门开的那段取值）的有 3 处：锁血、生态重置怪池选择、敌人倍数；接 Update（周期刷新，每次刷新取一次样）的有 12 处：60s内硝石采集量、1分钟内倒人数量、每分钟击杀量、玩家阶段表现锁定、本阶段生成量、本阶段击杀数、本阶段补给调用次数、本阶段死亡率、本阶段资源采集量、偶数阶段锁存、奇数阶段锁存、上期实际怪池。

两种接法的共同点是「不刷新就保持」，用来对抗局内数值抖动。同一个原语还能顺手做滑动窗口：60s内硝石采集量 = Subtract(硝石采集量, LockFloat(硝石采集量, Update:TriggerTimer 60))——当前累计减去 60 秒前的采样，得到的就是最近 60 秒的增量。功能 ④ 的 玩家阶段表现锁定 正是 Update 接法的例子。

③ 从「回血上限」到「血量下限」

这一步在算什么：游戏里没有「血量下限」参数，所以只能临时抬高「回血天花板」。

③ · 详解：公式与推演

游戏里没有「血量下限」这个参数。锁血的做法是把 HealthRegenerationMax 临时改成 Max(0.7, 当前血量)：回血只能回到上限以内，所以上限不低于 0.7 就等于血量不会掉到 0.7 以下；血量原本高于 0.7 时，上限被抬到锁定瞬间的血量，于是血量被钉在当前水平。理解这一点，功能 ④ 里 Then:4、Then:25 那套倍率才有意义——它们改的是回血强度，而锁血改的是回血天花板。

① 评级：Sequence + Reset 的周期状态机

② 防抖：每阶段只采样一次

这一步在算什么：加一层锁存，让评级在阶段中途不许跳档。

② · 详解：公式与推演

玩家阶段表现锁定 用 LockFloat(Update:轮转阶段周期Boolean)：Update 接法只在阶段信号到来时刷新一次，阶段中途评级怎么波动都不影响锁定值。所有啤酒判断读的都是锁定值（玩家阶段表现锁定 == 4/5/6），不是瞬时评级。这是「每阶段发一次奖」能成立的前提——不锁定的话，评级会在阈值上下反复穿越，奖励就会重复发放。

这一步在算什么：评级 6：无敌是把一个乘子变成 0，清图是刷一只一出生就自爆的单位。

⑥ · 详解：公式与推演

昏迷黑啤·危机庇护次数 = Sequence [0,1]；Next = TriggerFixedDuration(1, IfFloat(锁定 == 6))，Previous = TriggerDelay(21, TriggerFixedDuration(0.5, IfFloat(团队状态评估 ≤ 0.45)))——极度危急持续一段、再过 21 秒才消耗一次。昏迷黑啤·危机庇护激活 = And(团队状态评估 ≤ 0.45, 危机庇护次数 > 0)。

它进入 伤害抑制因子 的 A 分支：TriggerFixedDuration(20, In:危机庇护激活)。伤害抑制因子 是 If(Or(A, B:25 秒生态重置, C:Destroyer 刷出后 10 秒), Then:0, Else:1)，输出的 0 就是 敌人伤害 的 G 乘子——整条伤害链归零 20 秒，这就是无敌。同时 WaveSpawners[3]（Name:"清场机制"）的 Enabled.B 等于 TriggerDelay(1, TriggerFixedDuration(0.8, 危机庇护激活))，刷出 Enemies.ED_Destroyer（DisplayName:"清图大自爆"、Heal:-9999 让它一出生就死、死亡爆炸 RadialDamage:66666 / DamageRadius:20000 / MinDamagePct:1），这就是清图。「清图」本身没有独立的变量名，由这一个刷怪条目与这一只单位共同承担；若另有所指，未能确认。

两档阈值把三种啤酒分开：红岩要 团队状态评估 ≤ 0.75 且本阶段用过补给，昏迷黑啤要 ≤ 0.45。同一个 团队状态评估 被复用成分档依据，调阈值就是在调「哪种酒更容易出现」。

一条洞见：无敌是把一个乘子变成 0，不是加抗性。好处是自动覆盖所有伤害类型；代价是它和功能 ② 的减伤共用同一条 Multiply 链——伤害抑制因子 取 0 时，勘探者的 0.8 与 0.5 也一起被乘掉。这是隐含耦合，改动前要意识到。

另一条洞见：播报窗口与技能窗口的数字是手工凑的。Messages[4] 的 Reset 用 TriggerDelay(30, …)、Send/B/Enable 又是 16，Messages[5] 里写的是 15，与技能本身的 20 秒并不同源。改技能时长必须逐个核对 Messages[3]、[4]、[5]，不能只改一处。

① 前置：条件检测

① · 详解：公式与推演
  • 团队状态评估 = Min(钢铁与倒地权重 + 血量与护盾权重 + 全队弹药×0.2, 三倒以上则 0.20)（见功能 ⑥ 附录 H）。
  • 生态重置条件检测 = 团队状态评估 <= 0.4 AND 生态重置次数 == 1 AND NOT(昏迷黑啤·危机庇护次数 > 0)。注意第三项在原文里写作 "Mutate":"IfFloat"（小写 f），是源文件原样。
  • 生态重置次数 是一个 Sequence [1,0]（InitialOffset 1，Repeat false）：Next = 生态重置激活 持续 1s、Previous = Or(击杀 ED_Yes 后延迟 300s, SecondaryFinished 持续 1s)。即：用掉一次后进入冷却，冷却 300 秒或完成一个次要任务就恢复——这正对应作者描述里的「四:次要完成奖励」。
  • ⚠️ （未能确认）：Sequence 的 InitialOffset 取址语义无法从源文件判定。若按"索引"解释则初值 = Sequence[1] = 0（必须先激活过一次才满足 ==1，存在自举疑问）；若按"从末尾起算"解释则初值 = 1（一开始就可用，使用后归 0、完成次要任务后恢复），后者与 Previous 里挂 SecondaryFinished、以及 "有剩余次数才触发" 的设计一致。两种解释下 ==1 都表示"可用"。

  1. 生：WaveSpawners[1]「生态重置选择」 同时刷出 ED_Yes 与 ED_No 各 1 只（Locations:1、Diversity:2、Distance:2000，难度只有 100/66，很容易打）。两只都继承 ED_FlyingSmartRock，MaxPawnSpeed 0.01（悬停不移动），HealthRaw 200，抗性里把 电/爆炸/内部/辐射/毒/穿透 全设为 0（= 免疫），只留 火/腐蚀/冰冻/动能/物理 = 1——也就是说只能用常规枪械与火/酸/冰伤害打死，ED_Destroyer 的清场大爆炸也炸不掉这两颗石头（ExplosionDamageMultiplier: 0）。

    - 上升的是 ED_Yes → 生态重置激活 的 Value 触发 → 真 150 秒 → 执行重置；
    - 上升的是 ED_No → Lock 触发 → 把该布尔锁 166 秒 → 否决。
  4. 收尾：ED_Yes 的 Heal 是 {InitialRate:0, SwitchAfter:6, FinalRate:-10000}，出生 6 秒后自动掉血自毁（避免场上一直留着没被选的石头）；ED_No 的 Heal 是条件式——一旦"是"被击杀且持续 5 秒，ED_No 也开始 -1000/s 自毁。两者都会自己消失，不留残余单位。
  5. 超时（Lock 比 Value 长多少）：Lock = 166 秒、Value = 150 秒，差 16 秒。这是刻意的"否决窗口":ED_Yes 6 秒就会自毁、ED_No 在"是"死后 5 秒也会自毁，两个判断事件都挤在开头十几秒内；把"否"的锁定期设为比"是"的有效期长 16 秒，就能保证"否"的决定在时间上完全覆盖"是"的残留窗口，玩家不会在最后几秒被判成"是"。同理 生态重置怪池选择 也用 166 秒锁存，保证整个重置过程池子是同一个、不会中途重摇。
